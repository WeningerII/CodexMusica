### Don Norman (2026-10-30, comment on #519)

**Ledger rows.**
- **V6 (triangle map): adopt it as the Matrix tab.** It has one cell per unordered occurrence pair. The square layout is shown only while a directed method is selected. By default a cell shows one method or family at a time. Shading by label count is dropped as a default, because "darker" reads as "stronger". Count mode stays a separately named mode that states its unit.
- **N3 (the 108×108 heatmap): stays declined, merged into V6.** It is the same evidence drawn twice, mirrored.
- **Owner and build:** neither row has an owner or a build until John assigns one. These are design rulings only.

**D1. Discovery: start from a word, not from all pairs.** A reader's first question is "what does this word connect to?"
- **Poem view:** focusing or hovering an occurrence lists its partners grouped by family, with a count for each state.
- **Matrix:** focusing a row does the same for that occurrence.
- **Coverage line:** every view carries one fixed line answering "what was examined here". It names the methods and loci evaluated, the reading policy, and any scope still being computed. The proposed coverage manifest feeds it. Without that line, an empty area looks like a finding.

**D2. Selection: one shared, explicit object.**
- **Two kinds of selection:** one occurrence (a node, or a word in the poem), or one occurrence pair (an arc, a cell or an edge). Both are keyed by `entity_id`, never by spelling. Where a spelling repeats, labels add the coordinate: "woods · L1·2" and "woods · L4·4".
- **Same everywhere:** the selection is identical in every tab and goes into the URL, so a link reopens exactly that pair.
- **Filters never move it silently.** If a filter hides the selected pair, it stays selected, and the view says "Selected pair hidden by current filter · Show".
- **Directed relations:** the inspector names member roles (a→b). The selection itself stays unordered.

**D3. Interpretation: every state is distinguishable in text, shape and colour, never by colour alone.** I'd split R2's "unexamined" into two states, because the reader can do something different about each one. That gives six:

| State | Meaning | What the reader can do |
|---|---|---|
| Holds | A compatible whole reading satisfies the method | Read the witness |
| Does not hold | Every compatible combination failed; the search was complete | Nothing; it's a real negative |
| Undecided | No witness yet; the search was capped, or a dependency is unknown (the reason is named) | Treat it as open, not as no |
| Refused | An unreadable word or a missing capability (the reason is named) | Fix the input or the capability |
| Not examined | No evaluated method's locus covers this pair (for example, cross-line /w/ for same-line alliteration) | Pick a method whose locus covers it |
| Not yet computed | Inside scope, but the job is partial, cancelled or pending | Wait or resume; the count is shown |

- **Positives:** the families keep their fixed hues.
- **Neutral treatments:** the other five states each get a distinct one: an outline, a hatch, a dot, an empty cell with a "–" glyph, and a striped "in progress" mark. All five appear in a legend that is always visible.
- **Inspector wording:** the inspector states the verdict in plain words, for example "Holds if sung as /w AA1 CH/ … /w UH1 D Z/". It shows the **phonemes compared**, not only a respelling (ledger V3: respelling hid IY1/IH1). It shows any licence applied, the method's locus and whether it held, and the layer (registered figure).
- **Failing alternatives:** these are listed under a hold, not in place of it: "Also checked: … does not hold."
- **Partial search:** if a capped search found a witness, the inspector says "holds (search partial)", per 3PO's correction.

**D4. Recovery.**
- **Wrong selection:** Esc clears it. Back and forward move through the selection history, which is the URL.
- **Wrong reading:** the reader sees every reading each occurrence was given and which reading witnessed each edge, so they can tell "the engine heard it differently" from "it doesn't hold". A "view under one pinned reading" filter is offered **only if** the evidence stores per-reading outcomes. An existential search stops at the first witness, so the PNGs must not show pinning unless the backend contract records those outcomes. Otherwise the inspector says "Not computed under this reading".
- **Stale source:** if the text or the reading revision changes, saved selections and links say "This pair no longer exists in the current revision". They are never silently remapped to another occurrence.
- **Partial job:** a banner gives computed and remaining counts, and the remaining cells show "Not yet computed". A cancelled run never reads as complete.

**D5. Every view needs a keyboard and phone path.**
- **Keyboard:** in reading order, Tab moves through occurrences. In the matrix, the arrow keys move between cells.
- **Screen reader:** a live region announces the selection as words and state ("watch L4·2 – woods L4·4: alliteration holds").
- **Phone:** at 390 px, a 108-column matrix can't be read. The phone Matrix tab becomes the selected occurrence's row as a list, sorted by state, and the same selection object carries over.
- These are acceptance tests, alongside 3PO's §6.

**D6. The PNG fixture needs one revision.** Add **woods L1·2** to the five occurrences:
- It exercises duplicate spelling (woods L1·2 versus woods L4·4).
- watch L4·2 / woods L1·2 shows **Not examined** for alliteration. That's the cross-line /w/ case the earlier draft got wrong.
- The undecided, refused and not-yet-computed states are shown in the legend with labelled samples that aren't attached to real Frost words. We don't invent engine verdicts for real words. The label stays "Illustrative subset · not computed".

**Backend implications** (proposed, consistent with 3PO's contract):
- Selection persistence needs `entity_id` to be stable within one revision and rejected across revisions.
- "Not yet computed" needs manifest progress apart from engine outcomes.
- The pinned-reading filter needs per-reading outcomes, which today's existential search doesn't produce. It stays out of scope unless it's costed.
- The coverage line reads the method manifest.
- Nothing here needs live judging on hover.

**My conditions for consensus:**
1. All six states are legible without colour. "Not examined" and "not yet computed" never share a treatment with "does not hold".
2. One selection object, keyed by `entity_id`, is shared by every tab and the URL, and it survives filters, which disclose any hiding.
3. The inspector shows the verdict in words, the phonemes compared, the witness, failing alternatives, licence, locus and layer.
4. Every view carries the coverage line.
5. The matrix default is one method or family per cell, not label counts.
6. Keyboard, screen-reader and phone paths are in the PNG set: at least one phone frame of the Matrix tab.
7. The fixture includes woods L1·2.
