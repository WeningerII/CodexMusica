### Backend contracts (each marked IMPLEMENTED, PROPOSED, or 3PO-READ meaning 3PO's code reading that R2 has not verified)

**B1. Occurrence identity.** IMPLEMENTED: the stream addresses each word as (line, token ordinal) in `stream.lexical_tokens`. PROPOSED: that pair, plus a text hash, is the only ID any view, cache row or evidence record uses. A spelling is never an ID.

**B2. Per-schema locus and coverage.**
- IMPLEMENTED: every `RelationSchema` declares its spans' `locus` (line, line_final_token, line_initial_token, free_run, line_head_index and others) and its channels. `schema_read_fields(schema)` exists on `claude/english-sound-inventory` only, not on main.
- PROPOSED: a per-poem coverage table, one row per schema, recording which occurrence pairs its locus can bind and whether it was evaluated.
- A cell outside every evaluated schema's locus is **unexamined**, not "no match". There is no all-schema, all-pair claim.

**B3. Outcome, quantifier, completeness and witness, stored separately.**
- IMPLEMENTED:
  - `pair_satisfies` returns True, False, None or a Refusal.
  - `pair_satisfies_any` and `resolve_line_pair` return (answer, witness), where witness is the reading set that held.
  - Obligations are existential and prohibitions universal (standing rule 5).
  - The reading search is capped at 64 combinations (`READING_COMBO_CAP`). `reading_combos` knows whether its search was complete, **but that flag is not returned to callers**.
- PROPOSED: each evidence record carries `{outcome, quantifier: exists|forall, search: complete|capped|n/a, witness?, failing_readings?, refusal?}`. "Search cap" can only be shown once that flag is exposed, which is a small engine change, to be costed before it's promised.
- The states then map directly:
  - holds: exists, with a witness;
  - fails: no combination held, and the search was complete;
  - undecided: no combination held, and the search was capped or the judge answered None;
  - refused: a Refusal with its capability or reason;
  - unexamined: the B2 table says the cell wasn't evaluated.

**B4. Persistence and cache identity.**
- IMPLEMENTED: `comparator_fingerprint()` hashes 7 inputs, and a move discards the predictability memo. The lexicon carries `reader_scheme`, the supplement's sha256 and `ACCENT_RULES` ("accent-readings-2026-10-30").
- PROPOSED: a per-poem evidence row is keyed by (text sha, lexicon identity: scheme, supplement sha and accent rules, registry or comparator fingerprint, declaration, scope).
- Any key change invalidates the row. There's no partial reuse across a fingerprint move until a test proves which schemas are unaffected.

**B5. Workers, bounds and cancellation.**
- 3PO-READ: `library/analysis.py` `AnalysisSession` / `run_step` already gives resumable candidate traversal with schema-derived pruning. I have not read it yet and will before endorsing it as the host.
- PROPOSED: the matrix is a consumer of that pipeline's records, not a second traversal. Work is bounded per step and cancellable between steps, and a cancelled poem shows partial evidence with the rest marked unexamined.

3. **No invented edges.** A group never shows an edge the engine didn't return.
