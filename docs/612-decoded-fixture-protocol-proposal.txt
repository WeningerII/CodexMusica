Proposed criterion change, requiring owner/reviewer approval:
Replace identical baseline-encoded RunStore fixture files across images with
identical decoded payload content plus genuine per-image encoded fixture files.
JobStore fixture bytes remain identical. Within each arm, reuse the SAME complete
prepared-file bytes across both repetitions; never regenerate per repetition.
After-loaded and after-unloaded share the SAME candidate encoded fixture files.
Record each original/derived manifest separately. No identity restamping.

Concrete preparation algorithm (outside every timed or sampled workload):
1. Generate all random draft/replay/noise/declaration padding and run/request IDs
   once. Preserve one canonical decoded record set: 64 records, max-schema draft
   and replay arrays, both near-ceiling worker journals, declarations, explicit
   keys/run IDs and stable record metadata. Record complete byte/hash membership.
   The existing producer computes limits from actual schemas; do not hardcode
   smaller payloads. Prohibit source-semantic identity inside decoded fixture
   journals (the present synthetic producer does not add that field).
2. Verify the SAME decoded bytes with both unchanged images' draft/replay schemas,
   assertContinuationCapacity, declaration/worker/wire limits and record caps.
   Refuse mismatched derived schema maxima, missing/extra records, differing
   declarations, or too-small retained load. Preserve executed evidence per image.
3. In each image, call its actual encodeState for each state/checkpoint, then its
   actual decodeState; deep-compare every decoded field with the original record.
   Hash canonical decoded payloads independently and compare across images.
   Never use recoverState as a substitute for decodeState, change codec imports,
   substitute a shared source fingerprint or patch semantic identity strings.
4. Compare encoded envelopes field by field. Only semantic_identity is expected
   to differ, and must equal THAT image's genuine continuationSemanticIdentity.
   connector_contract, codec, encoding, decoded_bytes, payload SHA256 and compressed
   payload must match. If actual gzip bytes or other fields differ, stop for review
   rather than broadly permitting 'runtime differences'. Source/release identities
   belong in separate build receipts: release_id is NOT a wire-envelope field.
5. Record each actual wire size, outer serialized record/file size, decoded worker
   and declaration size, total retained size/count and difference. Assert identical
   wire lengths when only 64-hex semantic identities differ; verify rather than
   assume V8 allocation equivalence. Near-ceiling filling criteria remain unchanged.
6. Save baseline-encoded and candidate-encoded prepared-runs.json plus genuine
   byte hashes ONCE. Hash both outputs, preserving shared decoded input identity
   and exact producer/encoder/source/dependency identities. Bound physical bytes
   separately (combined decoded+two encoded sets may exceed the earlier single-set
   ~560 MiB estimate; recompute and enforce the approved cap, do not shrink input).
7. Each measured arm verifies its exact own manifest and the common input identity,
   copies into a private writable directory with existing required modes, and
   runs unchanged startup/workload. Both repetitions reuse original arm bytes.
   Compare candidate loaded/unloaded fixture hashes exactly; before/after compare
   decoded content and only approved envelope differences. All new validation and
   encoding is outside measurement; no per-arm random generation.
