# M-170: current attribution and continuation measurements

This supersedes the **work list**, not the historical observations, in
`RESULTS_TIME_AUDIT.md`. M-170 is **PARTIAL**: current measurements and the
measurement-driver repairs are banked here; cold 28-line continuation 2
times out, the missing round-10 records cannot be reconstructed, and
deployed-worker verification belongs to M-187.
No runtime comparator, threshold, cache capacity or deployment setting changes.

## Instrument and scope

`scripts/measure_lyric_continuations.py` calls the shipped `worker.run_one`
handler with real `finish` argv. Cold starts a process per call; warm retains
one process, while the CLI still constructs its own Reviser. The driver uses
`quality/fold_series.py`'s filler and fixed answer pool, seed 16, explicit
22- and 28-line plans, requesting eleven continuations after the initial call.
It answers actual pending single-line, group and batch questions. It does
not ask a model, substitute a grading result, select a faster seed, or restart
an early terminal run to manufacture a longer series.

These are local harness-handler measurements. The handler's buffered capture
is not the production HTTP/streaming transport, and this host is not Render.
Clocking includes the CLI work; outer wall time additionally includes child
startup on cold calls. Process CPU, host load, worker RSS and high-water marks
are recorded separately. A suspended call (exit 4) is not a finished song.
`answers_before` counts committed single/group answers in the journal before
the call; it excludes the submitted answer still in `pending`. A batch can
commit several answers during one continuation, so that count is not a count
of prior calls. All continuations answer the actual next question; none is an
identical-command repeat with an unchanged journal merely to expose a cache hit.
Memo tallies and the worker high-water mark are cumulative within a process:
warm rows must not be summed as if each were a fresh counter. RSS is the
post-call resident reading; the high-water mark captures earlier peaks.
Each numbered journal snapshot is the state returned by that call. The final
`state.json` also contains the driver's prepared answer for the next call;
preparing that answer does not count as executing another continuation.

The original fold driver could not reproduce today's experiment: it built
the draft from a plan that ignored `--lines`, used an unrelated `python3`
instead of its own interpreter, crashed on `propose_batch`, and exited
successfully after a refused fold. These are repaired. It also now refuses
to overwrite an existing draft/journal. The eleven focused controls run in
the existing offline production test command; none is a timing threshold.

The protocol was committed before the retained measurements in
`quality/results/m170_2026-09-17/PROTOCOL.md`. Runtime is main
`d6f729101777b440041a5d3c0854f2e04f1df204`; the measurement implementation is
local commit `8daf3486`. Every report contains the actual source and input
SHA256s, generated plan, interpreter, arguments and unchanged-source check.
The retained archive includes `measurement-source.bundle`, which carries that
exact local instrument commit on top of the named runtime base; the publication
commit's identity is separate from the identity of the measured source.
This is not a before/after speedup against the August audit: the planner and
mandate population have changed. The 22-line plan here has seven groups and
nine within-group pair occurrences; the old 22-line audit had 24 groups and
60 pairs. The current 28-line plan has thirteen groups and 37 within-group
pair occurrences. Changing the requested length also changes the drawn
mandate: the 22/28 comparison does not isolate a causal cost per extra line.

Exploratory calls were excluded: they exposed the line-count and batch-protocol
defects, and two pilot series were interrupted before the frozen serial run.
They do not supply any headline timing or equality claim below.

The equality reader is `scripts/summarize_lyric_continuations.py`. It compares
raw output again, rather than trusting the retained collector's preliminary
semantic digest: that digest included the internally generated `finish_bp`
path. The final collector and reader share the corrected normalization;
re-reading the retained raw files before and after that consolidation produced
the identical summary.
The reader excludes only that filename in the `BLUEPRINT` header, run-directory
paths, and the existing memo counters/disclosures. It compares journals as
complete JSON values. Empty output, absent pending journals, truncated arms,
refusals and unchanged-source failures cannot establish equivalence. The
focused controls mutate an actual finding and lyric text to ensure those
differences remain visible.

## Attribution without cProfile

Three separate cold initial calls were interleaved with three cold calls using
coarse nested component clocks. No behavior was stubbed. The clock wrapper
passes arguments and return values unchanged and accounts for exceptional
exits. **Exclusive CPU** subtracts instrumented children; inclusive component
rows overlap and must not be added. Uninstrumented remainder and startup are
not allocated to an invented component.

| repeat | bare outer wall, seconds | clocked outer wall, seconds | clocked CLI CPU, seconds |
|---|---:|---:|---:|
| 1 | 14.836 | 13.837 | 13.657 |
| 2 | 14.273 | 15.213 | 15.065 |
| 3 | 14.391 | 14.139 | 13.987 |

All six initial outputs agree after excluding the explicitly named temporary
paths and memo disclosures. Their spread does not establish a timer overhead
or a speedup. In particular, no cProfile percentage is multiplied by a bare
total to estimate recoverable time.

| component | exclusive CPU over the three clocked repeats, seconds | calls per repeat |
|---|---|---:|
| relation `line_pairs_for` | 7.075 / 8.062 / 7.009 | 96 |
| floor `RhymeField.field` | 2.493 / 2.766 / 2.519 | 101 |
| `Lexicon.__init__` | 2.483 / 2.635 / 2.723 | 5 |
| remaining `Reviser.__init__` work | 1.049 / 1.015 / 1.133 | 1 |

**The extra `group_merges` grade is not the large cost the old ranking
suggested.** The first clocked repeat makes eleven extra grade calls there,
eleven corresponding `build_stream` calls, and spends about 0.145 CPU seconds
in those grades including their children. The expensive path is the separate
merge-satisfaction schema search: 74 `line_pairs_for` calls, about 7.54 CPU
seconds inclusive in that repeat. Removing a redundant grade would not remove
that search. These measurements establish attribution, not permission to
remove a semantic check.

## Fields and cross-request state

The fixed-word probe is committed as
`quality/results/m170_2026-09-17/predicate_probe.py`. It asks the actual field
implementations at the shipped declaration, not an approximation of either.

| word | floor field | revision field | floor-only candidates | revision-only candidates |
|---|---:|---:|---:|---:|
| stone | 1,615 | 870 | 745 | 0 |
| door | 2,133 | 1,235 | 898 | 0 |
| light | 2,530 | 1,191 | 1,339 | 0 |

The fields are **not interchangeable**. `RhymeField.field` uses a scalar cut
on its indexed pronunciation; `_field_one` additionally applies the declared
relation admission and relation-specific cut using the grader's pronunciation
comparison. The complete differing word lists are retained. These are fixed
counterexamples, not a population estimate or a proposal to change the floor.

Holding a Reviser and changing its declaration is likewise unsafe. Its matrix
key is `(lines, promotion, profile)`, with declaration and lexicon invariant
for the instance. For `we keep the stone` / `they shut the door`, the probe
changes channel weights: the held matrix still returns total **0.815**, while
a fresh Reviser under the new declaration returns **0.564**. Other instance
keys similarly rely on fixed configuration: the slot cache omits the full
declaration/lexicon, the anchor cache keys word/promotion, and the field cache
does not itself carry every declaration coordinate.

This is a counterexample to the audit's proposed unrestricted reuse, not a
defect in the shipped fresh-Reviser lifecycle. M-217 already implemented the
alternative: process memos with wider declaration/lexicon keys, bypasses,
bounds and regression coverage. No held-Reviser optimization is introduced.

## Read or repeat the experiment

All retained measurement files are in
`quality/results/m170_2026-09-17/measurements.tar.gz`; the excluded pilots are
not in that archive. It contains 206 raw files and an internal `RAW_SHA256SUMS`.
The adjacent `summary.json` is the reader's output, and `predicate-results.json`
contains the complete fixed-word differences. From `lyric-harness`:

```sh
mkdir -p /tmp/m170-receipts
tar -xzf quality/results/m170_2026-09-17/measurements.tar.gz -C /tmp/m170-receipts
(cd /tmp/m170-receipts && sha256sum -c RAW_SHA256SUMS)
python3 ../scripts/summarize_lyric_continuations.py /tmp/m170-receipts
git bundle verify /tmp/m170-receipts/measurement-source.bundle
```

The bundle requires the recorded `d6f72910` base and contains the exact
`8daf3486` measurement source. For new runs, use a fresh output directory,
the runtime requirements in `mcp/requirements-runtime.txt`, and the verified
assets staged by `quality/fetch_data.py`. Run the arms **serially**:

```sh
for lines in 22 28; do
  for mode in warm cold; do
    python3 ../scripts/measure_lyric_continuations.py --mode=$mode --lines=$lines --folds=11 --out=/tmp/m170-new/series-$mode-$lines
  done
done
```

For the initial attribution controls, use `--mode=cold --lines=22 --folds=0`
with and without `--components`, interleaving three repeats of each in new
`bare22-1`/`timed22-1` through `bare22-3`/`timed22-3` directories. Run the
fixed-word probe from `lyric-harness`:

```sh
python3 quality/results/m170_2026-09-17/predicate_probe.py
```

A completed bounded experiment can contain a timeout. The collector returns
failure for that arm, and the reader's `complete: false`/`equal: false` means
that full equivalence was **not established**, not that different successful
answers were observed. A later study needs either a justified separate longer
measurement protocol or a correctness-preserving performance repair before it
can claim the missing cold 28-line continuation costs. This audit supplies
neither and leaves that requirement open.
