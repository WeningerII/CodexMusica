## Reader changes

`scripts/battery_inspect.mjs` emits inspection version 2:

- Refusal source, closed category and local equality group per song. Only the
  actual count-mismatch template produces expected/actual line counts.
  The group identifies identical tool/source/message triples; it does not mean
  identical requests or a common cause across different messages. Unknown
  messages remain `unclassified`; absent messages remain null.
- Recorded proposer calls, seconds, longest-call seconds, retries, wait seconds,
  empty answers and cost, plus plan size and replay-memo counts. Missing records
  remain null. Provider time and waits may overlap; do not sum these as disjoint
  components or subtract them to claim a measured harness-only duration.
- Latest recovery state/phase, round, completed journal proposal count,
  accepted-draft line count and provider uncertainty flags. This is a snapshot,
  not a history or a count of accepted edits. It does not decode tool checkpoint
  envelopes or infer a phase from a timeout.
- Missing transcript and malformed-row disclosure. The existing transcript
  size bound also protects JSON snapshots. A skipped or absent record is not a
  zero-work result.

New string fields use closed vocabularies. Refusal contents and equality-map
keys never leave the reader. Driver partial-turn rows and `last error` tails
are excluded just as they are in the live workflow. The existing `tools[].ms`
field retains its historical seconds representation for compatibility; new
timing field names state their units.

`scripts/battery_archive.mjs summary` now inspects surviving records even when
`summary.json` is missing, retaining `state: no_summary`. The new encrypted
restore/CLI regression initially failed on the old early return and passes
after this repair. The existing Battery inspect workflow already calls this
command; no workflow or secret configuration is changed.
